# v0.6.0 Duplex Read-Only SysEx Probe

## Goal and boundary

Implement the first functional original-KATANA-100 SysEx input/output path while
keeping it isolated from live pedalboard actions. Version 0.6.0 is a bounded
diagnostic release: it sends predefined RQ1 reads, receives and validates DT1
replies, and records evidence. It does not make queried state authoritative,
enable runtime synchronization, or expose arbitrary DT1 writes.

The only emitted DT1 values are the fixed editor-mode enter/exit handshake around
`current-selection`. Editor exit is attempted from `finally` after success,
timeout, interruption, or another failure.

## Implemented surface

- `midi-inputs` enumerates inputs without opening a port.
- Input and output names resolve independently by exact, case-insensitive exact,
  or unique case-insensitive substring match.
- `MidoMidiTransport.openInput()` copies payload-only SysEx data and a monotonic
  timestamp into a Mido-independent message.
- `KatanaSysExProbe` opens input before output, owns one serialized request at a
  time, parses on the caller thread, and correlates device ID, DT1 command,
  address, expected length, checksum, and connection epoch.
- `sysex-probe` requires explicit `--model`, `--input`, `--output`, and `--read`.
- Targets are `current-selection`, `effect-states`, and `panel-snapshot`.
- Timeouts and retries are bounded CLI values; defaults are discovery starting
  points, not hardware constants.
- Output contains complete sent/received bytes, fields, checksum status, timing,
  attempts, decoded values, and explicit errors.
- Sanitized JSON capture is optional, refuses replacement, and requires `SAVE`
  after the initial `READ` hardware confirmation.

## Safety behavior

- Cancellation before `READ` opens no port and sends no MIDI.
- The input is listening before the output can send a request.
- Wrong-address and malformed replies are retained but cannot satisfy a request.
- No raw address, generic RQ1, generic DT1, or parameter write is exposed by CLI.
- Existing configure/onboard/doctor and normal dry-run behavior remain unchanged.
- Probe observations do not update `KatanaController.effectState`.

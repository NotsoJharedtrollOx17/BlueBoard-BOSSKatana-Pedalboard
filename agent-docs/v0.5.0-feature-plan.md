# v0.5.0 Mk I SysEx Protocol Core

## Goal and evidence boundary

Implement the pure, hardware-independent SysEx foundation required by the revised
v1.0.0 state-awareness specification. Standard Program Change and Control Change
remain the only active amplifier-control paths.

Version 0.5.0 does not add a MIDI input, open or send through a new runtime port,
query the amplifier, synchronize state, or expose SysEx through configuration,
actions, or CLI. Passing byte-level tests is source evidence only; it does not
prove that the target amplifier accepts any candidate address.

## Public protocol interfaces

- `MidiCommand.data` continues to store complete wire bytes. SysEx builders include
  `F0` and `F7`; parsing a Mido payload requires `includesFraming=False`.
- `katana/protocol.py` provides `KatanaSysExFrame`, `encodeBase128`,
  `decodeBase128`, `incrementAddress`, `calculateRolandChecksum`,
  `verifyRolandChecksum`, and `parseKatanaSysEx`.
- `createSysExRead(deviceId, address, size)` is the public pure RQ1 builder.
- `createSysExData(deviceId, address, data)` is a low-level DT1 builder reserved
  for protocol tests and the future editor-mode guard. It is not re-exported from
  the Katana package or connected to a runtime action.
- Invalid types, booleans used as integers, non-seven-bit bytes, malformed
  framing, invalid headers/commands/checksums, empty DT1 data, malformed or zero
  RQ1 sizes, and base-128 overflow are rejected.

## Registry policy

Evidence values are `official`, `capturedMkI`, `communityMkI`, `legacyKatana`,
`inferred`, and `unverifiedPlaceholder`. Provenance is independent from access:

- reads are `none`, `probe`, or `production`;
- writes are `none` or `validated`;
- production reads and validated writes require `official` or `capturedMkI`
  evidence.

The registry contains six one-byte strict-boolean temporary-patch candidates for
the original `katana100`: Boost, Mod, FX, Delay, Reverb, and Send/Return. The first
five are `communityMkI`; Send/Return is `legacyKatana`. All use
`firmwareRange="unknown"`, `readAccess="probe"`, and `writeAccess="none"`.

Current-selection operations, broad panel snapshots, active-member selectors,
deep effect parameters, and writable definitions remain excluded.

# v0.4.0 Reliability Evidence Prerelease

## Goal

Make v0.4.0 the final Windows original-KATANA-100 (MkI) hardening prerelease.
It records live-use evidence and recovery behavior without adding speculative MIDI
capabilities. The next stable milestone is v1.0.0 for this Windows/MkI target.

## Implementation checklist

- [x] Add `recordPedalboardSession.ps1`, which creates a timestamped ignored JSON
  session log and remains dry-run unless `-Active` is explicit.
- [x] Add `blueboard-katana run --duration-seconds N` for a positive bounded run;
  duration completion stops cleanly with exit code 0 and records `duration-limit`.
- [x] Include the reason for normal or interrupted stopping in the final metrics
  record while retaining the existing JSON logging format.
- [x] Add a Windows/MkI v0.4 acceptance record for onboarding, A-D, reconnect,
  cleanup, LEDs, and a 60-minute session.
- [x] Keep SysEx, authoritative state, persistent state LEDs, expression input,
  MkII hardware validation, and Linux hardware validation out of scope.

## Public interfaces

```text
blueboard-katana run [--duration-seconds SECONDS]

.\recordPedalboardSession.ps1 [-Active] [-DurationMinutes MINUTES]
  [-LogDirectory PATH] [-Debug] [-LedFeedback]
  [-Name SUBSTRING] [-Address ADDRESS] [-ScanTimeout SECONDS]
```

`recordPedalboardSession.ps1` writes to `logs/pedalboard-sessions` by default.
It is ignored by Git and prints the resulting log path. `-Active` is the only
wrapper option that enables configured actions. Ctrl+C keeps the existing exit
code 130; a requested duration ends with exit code 0.

## v1.0.0 definition

v1.0.0 is stable for the original BOSS KATANA-100 (MkI) on Windows. It requires
the recorded acceptance checks, automated/package validation, removal of the
alpha development classifier, and a release note that labels Linux and MkII
hardware support experimental. It does not require SysEx, expression control, or
authoritative amplifier-state synchronization.

## Release decision

v0.4.0 is accepted as a Windows/MkI reliability prerelease based on the recorded
2026-08-29 smoke sessions and physical reconnect observations. The duration-limit
and 60-minute rehearsal checks remain v1.0.0 release gates, not blockers for this
prerelease.

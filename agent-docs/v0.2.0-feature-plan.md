# v0.2.0 Windows-First Setup and Reliability Release

## Summary

- Treat the current v0.1.0 implementation as the functional MVP: 83 tests and Ruff currently pass, and the original KATANA-100 A/C/D path is hardware-validated.
- Focus v0.2.0 on easier configuration, clearer diagnostics, model-correct tooling, and Windows reliability—not expression control, SysEx, or persistent amplifier-state LEDs.
- Qualify the release on the original KATANA-100 under Windows. Preserve Linux scripts and CI as experimental, without claiming Linux hardware validation.

## Implementation Changes

- Introduce one internal model/profile registry used by configuration generation, summaries, validation, and effect probing. It must distinguish:
  - Original `katana100`: grouped Booster/Mod CC16, Delay/FX CC17, Reverb CC18, Send/Return CC19.
  - `katana100MkII`: independent CC16–CC21 effects.
- Convert `configure` into a hybrid wizard:
  - Discover and select the main Katana output, prompting with a numbered list only when ambiguous.
  - Prompt for amplifier model because MIDI port names cannot identify the generation.
  - Default the original KATANA-100 to the validated Panel-first layout: A=Panel/PC4, B=A:CH2/PC1, C=Booster/Mod, D=Delay/FX.
  - Prompt for MIDI channel, optional firmware provenance, and BlueBoard selection when multiple devices appear.
  - Explain and confirm the initial predicted effect states before generating toggle bindings.
  - Display the complete A–D mapping and obtain confirmation before writing.
  - Never open the Katana port or send MIDI during configuration.
  - When replacing an existing local profile, default to cancellation and create a timestamped ignored backup before an explicitly confirmed replacement.
- Add a read-only `doctor` command and PowerShell wrapper that validate the configuration, Python/runtime compatibility, MIDI backend, configured output resolution, and BlueBoard discovery. Return exit code 0 when ready and 2 for actionable readiness failures.
- Print a concise startup summary for `run`: model, output, A–D mapping, predicted-state warning, and whether actions are dry-run or enabled. Preserve lazy MIDI opening.
- Make `probe-effects` profile-aware:
  - Derive labels and CCs from the selected model/configuration.
  - Support only configured switches.
  - Derive the default program from the first preset binding.
  - Require `--model` when probing through a raw output instead of a configuration.
  - Remove the current MkII-only behavior that is unsafe or misleading for the actual MkI amplifier.

## Public Interfaces

- Extend `configure` with `--model`, `--layout`, `--midi-channel`, `--firmware`, `--address`, `--non-interactive`, and `--accept-profile-state-defaults`; retain the existing discovery and override flags.
- In non-interactive mode, unresolved model/device/port choices must fail clearly instead of guessing.
- Add `blueboard-katana doctor --config PATH [--scan-timeout SECONDS]`.
- Update `probe-effects` to accept either `--config PATH` or `--output NAME --model MODEL`.
- Keep the JSON configuration schema backward-compatible. Existing local profiles should load without migration.
- Update package descriptions and banners from MkII-specific wording to model-neutral wording, then set both version declarations to `0.2.0`.

## Validation and Release

- Add automated coverage for both model profiles, exact generated mappings, interactive and non-interactive configuration, ambiguous device selection, cancellation, backups, predicted-state confirmation, doctor results, profile-aware probes, and read-only guarantees.
- Preserve all existing tests and add wheel/sdist build plus clean-wheel smoke tests for `--version`, `validate`, and fixture replay.
- Keep Windows and Linux Python 3.10/3.12 CI regression coverage; label Linux hardware support experimental in the README and release notes.
- Perform the Windows acceptance sequence on a fresh local configuration:
  - Record exact firmware, driver, Tone Studio, Windows, and port information.
  - Confirm Panel/PC4, A:CH2/PC1, Booster/Mod CC16, and Delay/FX CC17.
  - Verify dry-run A–D events before enabling actions.
  - Test independent Katana and BlueBoard reconnects, Ctrl+C cleanup, momentary LEDs, and a one-hour rehearsal session.
- Update the README and release roadmap with the streamlined first-run path, Windows-qualified/Linux-experimental status, predicted-state limitation, and dated hardware evidence.
- Merge `dev` into `main` and create the v0.2.0 tag only after automated, packaging, and Windows hardware acceptance checks pass.

## Assumptions

- The guided PowerShell/CLI workflow is the supported Windows experience; no separate double-clickable CMD menu is added.
- Panel-first remains the recommended MkI profile despite its predicted-state limitation; external panel, knob, or Tone Studio changes can still make local effect state stale.
- v0.2.0 remains an alpha release. Expression pedals, SysEx readback/editing, authoritative state synchronization, and amplifier-state LEDs remain deferred.

# v0.4.0 Windows Original-KATANA-100 Acceptance

**Target:** Original BOSS KATANA-100 (MkI) on Windows  
**Status:** v0.4.0 prerelease accepted after Windows/MkI smoke validation on
2026-08-29. The v1.0.0 endurance record remains pending.

## 2026-08-29 observed result

- Dry-run, active A-D routing, and momentary LED feedback completed without
  unexpected action or LED-write failures in the recorded session logs.
- The BlueBoard physically disconnected and reconnected during an active session;
  routing resumed and the log recorded `reconnects: 1`.
- The Katana physically disconnected and reconnected. A real WinMM send failure
  was isolated; the next mapped action reopened `KATANA 1` and the log recorded
  `katanaReconnects: 1`.
- Ctrl+C produced final metrics with `stopReason: interrupted`.

These observations accept the v0.4.0 reliability prerelease. They do not replace
the separate 60-minute, duration-limited v1.0.0 rehearsal gate.

## Required acceptance sequence

- [ ] Run `./onboardPedalboard.ps1` and confirm a saved profile is checked READY
      without opening a MIDI output or sending a message.
- [ ] Run `./diagnosePedalboard.ps1` and confirm fresh READY discovery.
- [ ] Run `./recordPedalboardSession.ps1 -DurationMinutes 5` and verify the JSON
      log ends with `stopReason: duration-limit` and no Katana commands.
- [ ] Run `./recordPedalboardSession.ps1 -Active -DurationMinutes 5`; confirm A

- [ ] Repeat the active smoke test with `-LedFeedback`; confirm momentary LEDs
      do not claim amplifier-state synchronization.

- [x] Stop an active session with Ctrl+C; confirm final metrics and clean return.

# v0.7.0 Runtime SysEx State Bootstrap and Recovery

## Goal and boundary

Integrate the proven Mk I duplex reader into an active BlueBoard run without
turning SysEx into a general write surface. Version 0.7.0 observes the six live
effect flags at startup and after detected Katana transport recovery. Standard
Program Change and Control Change remain the only runtime actuation plane.

Post-PC/CC verification, polling, unsolicited external-change handling, current
selection, persistent state LEDs, arbitrary addresses, and deep parameter writes
remain outside this release.

## Implemented surface

- [x] New Mk I profiles carry independent `inputName`/`outputName`, device ID,
  and bounded `stateSync` settings; legacy profiles load with sync disabled.
- [x] Onboarding and doctor enumerate both directions without opening either.
- [x] Diagnostic and runtime reads share one strict request/reply matcher.
- [x] One Katana worker serializes runtime RQ1, PC, and CC operations without
  blocking the BlueBoard asyncio notification consumer.
- [x] Startup publishes one atomic six-effect snapshot with connection epoch,
  observation time, source, raw failure, and strict unknown handling.
- [x] Booster/Mod and Delay/FX group derivation preserves individual and both-on
  member states.
- [x] Send failure closes both ports, increments the epoch, invalidates state,
  and makes the next operation reopen input before output and resynchronize.
- [x] Preset selection stays available in degraded mode; unknown toggles fail.
- [x] PC briefly labels configured state predicted/stale, then queries the newly
  loaded temporary patch; toggles read before CC and verify with readback afterward.
- [x] Runtime synchronization accepts only exact-firmware definitions explicitly
  authorized for production reads.

## Source acceptance

- Runtime tests cover full and partial snapshots, both-on groups, post-PC temporary
  patch reads, read-before-toggle, post-CC verification/mismatch, unknown toggle
  rejection, non-blocking queue submission, failure invalidation, and resync.
- Existing config, onboarding, standard MIDI, diagnostic SysEx, BLE, LED, and
  packaging behavior remains in the full regression suite.
- Dry-run, configure, onboard, and doctor open no MIDI ports.

## Release state

Source implementation is complete, but the production registry and hardware
release gate remain pending. The existing successful ignored captures omit the
exact BOSS physical firmware result and do not provide a clean one-effect-at-a-time
reproduction/restoration record for every address. Do not promote definitions,
merge to `main`, or tag `v0.7.0` until
`v0.7.0-sysex-runtime-acceptance.md` is complete.

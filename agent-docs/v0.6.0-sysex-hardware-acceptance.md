## Ordered test sequence

### 1. Enumerate inputs — no port open, no MIDI sent

```powershell
.\listKatanaMidiInputs.ps1
```

Expected: one clearly identifiable main KATANA input. Record every returned name.
Stop if none exists or the intended input cannot be distinguished.

### 2. Enumerate outputs — no port open, no MIDI sent

```powershell
.\listKatanaMidiOutputs.ps1
```

Expected: the previously validated main output, normally `KATANA 1` on this
machine. Record every returned name; do not infer generation from names alone.

### 3. Read current selection — editor handshake plus one read

Replace both names below with the exact results from steps 1–2:

```powershell
.\probeKatanaSysEx.ps1 --model katana100 `
  --input "KATANA 1" --output "KATANA 1" --read current-selection `
  --save-fixture ".\logs\sysex-current-selection-panel.json" --debug
```

Type `READ` only after rechecking the model, ports, backup, and volume. Expected:
input opens before output; editor enter is sent; a checksum-valid DT1 at
`00 01 00 00` returns two bytes; editor exit is sent; the observation is Panel or
a conservatively reported unknown raw value. Type `SAVE` only after inspecting the
traffic. Stop if the exit line is missing, the checksum is invalid, the address is
unexpected, or the amp does not remain usable afterward.

Repeat after selecting each configured Program Change with the already validated
`katana-test` command, then restore Panel. Record raw selection bytes rather than
inventing Bank B meanings.

### 4. Read the six live effect flags — reads only

```powershell
.\probeKatanaSysEx.ps1 --model katana100 `
  --input "KATANA 1" --output "KATANA 1" --read effect-states `
  --save-fixture ".\logs\sysex-effect-states-baseline.json" --debug
```

Expected: six serialized RQ1 requests and six checksum-valid, exact-address,
one-byte DT1 replies decoded strictly as `00`/off or `01`/on. Exit code 2 means at
least one required observation was not validated; preserve the console/log but do
not promote any registry entry.

For reproduction, change exactly one effect state outside the probe, close the
other MIDI client again, rerun with a new fixture name, and confirm exactly the
expected address/value transition. Repeat on/off and restore the original state.
Use the model-correct grouped Booster/Mod and Delay/FX behavior; never collapse two
individual replies into one assumed boolean.

### 5. Capture the optional front-panel range — broad read, run last

```powershell
.\probeKatanaSysEx.ps1 --model katana100 `
  --input "KATANA 1" --output "KATANA 1" --read panel-snapshot `
  --save-fixture ".\logs\sysex-panel-snapshot.json" --debug
```

Expected: one or more checksum-valid DT1 chunks whose start addresses fall inside
the predefined `00 00 04 00` extent. Gaps and multiple chunks are valid; do not
treat the result as one contiguous production state record.

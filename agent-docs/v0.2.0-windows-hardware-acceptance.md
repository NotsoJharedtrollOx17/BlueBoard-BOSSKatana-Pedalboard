# v0.2.0 Windows hardware acceptance

**Prepared:** 2026-08-24  
**Target:** Original BOSS KATANA-100 (MkI) on Windows  
**Status:** Pending physical execution; do not merge to `main` or tag v0.2.0 yet.

## Existing evidence carried into the release candidate

- `KATANA 1` accepted Program Change 0, grouped Booster/Mod CC16, and grouped
  Delay/FX CC17.
- BlueBoard A/C/D routing worked end to end with explicitly enabled actions.
- The exact firmware, B/Program Change 1, independent reconnects, and endurance
  were not recorded and therefore remain pending.

## Acceptance sequence

- [ ] Start from a fresh ignored `katana-pedalboard.local.json`.
- [ ] Run `setupPedalboard.ps1` and confirm v0.2.0.
- [ ] Run `configurePedalboard.ps1`; select `katana100`, Panel-first, `KATANA 1`,
      and the intended BlueBoard.
- [ ] Confirm the generated summary is A=Panel/PC4, B=A:CH2/PC1,
      C=Booster/Mod/CC16, and D=Delay/FX/CC17.
- [ ] Run `diagnosePedalboard.ps1`; confirm READY and no amplifier change.
- [ ] Run `runPedalboard.ps1 --debug`; confirm A-D dry-run logs and no amplifier
      change.
- [ ] Run with `--execute-actions`; physically confirm A/PC4, B/PC1, C/CC16,
      and D/CC17 from the recorded starting states.
- [ ] Run `probeKatanaEffects.ps1` for one grouped switch; confirm model-correct
      label/CC and OFF cleanup.
- [ ] Disconnect/reconnect the Katana while the BlueBoard remains connected;
      confirm the next action reopens the MIDI output once.
- [ ] Disconnect/reconnect the BlueBoard while the Katana remains connected;
      confirm routing resumes without restarting the application.
- [ ] Confirm Ctrl+C closes both resources and prints final metrics.
- [ ] Smoke-test `--led-feedback` without treating momentary LEDs as amp state.
- [ ] Run continuously for one hour and record packets, events, actions, action
      failures, BLE reconnects, Katana commands, failures, and reconnects.
- [ ] Restore the original amplifier sound/effect state.

## Production-read promotion gate

For each of Boost, Mod, FX, Delay, Reverb, and Send/Return:

1. Save a baseline `effect-states` fixture.
2. Change exactly that flag using a validated standard control or physical/Tone
   Studio operation, then close the competing MIDI client.
3. Save the changed fixture and verify only the intended/coupled physical behavior.
4. Restore the original state, save a restoration fixture, and verify it physically.
5. Sanitize host paths, addresses, and identifiers; add model, exact firmware,
   physical observation, and restoration metadata to the tracked fixture.
6. Change only that `ParameterDefinition` to `capturedMkI`, the exact firmware,
   and `readAccess="production"`. Keep `writeAccess="none"`.

Current-selection/editor-mode evidence is not a v0.7.0 gate.

## Runtime sequence

After all six definitions are promoted and the generated profile records the same
firmware:

```powershell
.\diagnosePedalboard.ps1
.\runPedalboard.ps1 --debug --execute-actions
```

- [ ] Doctor resolves input/output independently and opens neither.
- [ ] Active startup opens input before output and logs six `source=queried` values.
- [ ] Physical/Tone Studio state matches the startup snapshot.
- [ ] Changing state before launch changes the next startup snapshot.
- [ ] C/D use the queried grouped state; both-on test data remains representable.
- [ ] A/B mark prior observations stale and load only labeled predictions.
- [ ] Unplug/replug Katana; a detected failure invalidates state and the next

- [ ] A late pre-reconnect reply cannot update the new epoch.
- [ ] Ctrl+C joins the worker and closes both MIDI ports without hanging.
- [ ] Original amplifier state is restored.
